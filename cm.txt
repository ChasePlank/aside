Port Tropical Punch in as the third game, and fix an engine bug it exposed

aside.games.fruitjump -- the playable Java version: Fruit Jump, a
side-view platformer, plus the top-down room-crawler underneath it. Its
engine (physics, level generation, enemy AI, the AI director) moved
across with a package rename, same as the survival game did. All three
games now run in one process from the library.

Engine features this needed, both real rather than workarounds:

- handleKeyReleased on UiScreen, routed through UiManager and the host.
  A platformer needs to know when a held key stops being held; nothing
  before this cared about releases.

- Per-screen drawing resolution. UiScreen.canvasWidth()/canvasHeight()
  default to 1280x720 and screens override them. Fruit Jump renders at
  1600x1200 by design and is no longer forced down to the engine size;
  the host scales whatever a screen declares.

THE BUG IT EXPOSED, in my own code since the engine was written:

fit() centred the SCALED canvas. But setScaleX/Y pivots at the NODE
CENTRE, not the top-left, so scaling already keeps the centre where it
is -- centring the scaled result as well double-counted the shift and
pushed the image off-centre by (1-s)*size/2.

It was invisible until now because every previous screen used a canvas
the same size as the host, so s was 1 and the pivot did not matter.
Fruit Jump is the first screen with a different resolution, and it
rendered in the corner. Fixed to centre the unscaled canvas.

Also: each GameplayScreen/RoomsScreen built its own StackPane root
containing the shared canvas. A JavaFX node can have only one parent, so
that silently REPARENTED the canvas away from the visible root and the
screen drew to a node nobody could see -- a black window with no
exception anywhere. Removed; UiScreen owns the canvas.

And: Resize listeners alone are not reliable for fitting, because a
screen created while the window is still settling can be fitted to a size
that no longer applies and never corrected. UiManager now refits the top
screen before each frame -- four numbers of arithmetic is cheaper than
the bug.

Known cosmetic issue: Fruit Jump's 4:3 canvas letterboxes inside the
16:9 window. Correct, but the canvas size or the window aspect may want
revisiting.
